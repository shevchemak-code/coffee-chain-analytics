# Coffee Chain Analytics — AI-enhanced

Analytics dashboard for a small coffee chain (5 shops, 12 months of operational
data) with one production-grade AI feature: a **review theme digest** that turns
raw customer reviews into a grounded, structured brief (themes, severity,
verbatim evidence, recommended actions).

This repository is a solution to the take-home assignment described below. The
discovery reasoning is in [DISCOVERY.md](DISCOVERY.md); how production quality
would be measured is in [EVALS.md](EVALS.md); the failure-mode catalogue is in
[docs/EDGE_CASES.md](docs/EDGE_CASES.md).

---

## How to run

**Single command** (same as the original app — the AI feature degrades
gracefully without an API key):

```bash
docker compose up
# or
pip install -r requirements.txt && python -m uvicorn main:app --reload
```

The dashboard is at `http://localhost:8000`. On first start the SQLite database
is seeded automatically (`python seed.py` if you want to do it manually).

### Enabling the LLM feature

Without configuration the app runs fine: the **Insights** tab shows the
deterministic review stats with an "AI digest unavailable" note. To get real
digests, provide any Anthropic or OpenAI key:

```bash
export LLM_PROVIDER=anthropic          # or "openai"
export ANTHROPIC_API_KEY=sk-ant-...    # or OPENAI_API_KEY
python -m uvicorn main:app --reload
```

See [.env.example](.env.example). The provider layer (`ai/providers.py`) uses
small, cheap models by default (Claude Haiku / gpt-4o-mini) — see EVALS.md for
the cost/latency rationale.

### Running the tests

```bash
pip install pytest
pytest tests/ -q
```

The suite runs entirely offline: a scripted `FakeProvider` stands in for the LLM
and exercises both the happy path and the failure modes (hallucinated citations,
invalid JSON, provider outages, empty periods). See `tests/`.

## The AI feature

**Surface:** a new *Insights* tab in the dashboard — pick a shop and a period,
get a digest.

**Path:** `GET /api/insights/review-digest?shop_id=&date_from=&date_to=`

1. **Deterministic assembly** (`ai/digest.py`): reviews + aggregate stats for the
   period and the previous equal-length period are computed in SQL and serialized
   into the prompt. Nothing numeric is generated by the model.
2. **Versioned prompt** (`ai/prompts/review_digest_v1.md`): Markdown + YAML
   front-matter, with the reasoning for the format written into the file itself.
   The version id is returned in every response and keys the cache.
3. **Structured model output**: forced JSON (tool use on Anthropic,
   `response_format` on OpenAI) against a schema owned by the validator.
4. **Guardrails before display**: schema validation, then a grounding pass —
   every cited `review_id` must exist in the input batch and every evidence
   quote must be a verbatim substring of a real review. Unverifiable themes are
   dropped and reported.
5. **Graceful degradation**: no reviews, no API key, provider error, unparseable
   or ungrounded output — every failure returns HTTP 200 with `degraded=true`,
   a machine-readable `reason`, and the deterministic stats, so the page never
   breaks and never shows unverified model text as fact.
6. **Caching**: in-process TTL cache (15 min) keyed by (shop, dates, prompt
   version); `refresh=true` bypasses.

Try it on the planted signal: shop **Riverside Coffee**, 2025-10-01 → 2025-12-31
— a cluster of milk-quality complaints the digest should surface as a high-severity
theme.

## Original assignment

You have a working analytics dashboard for a small coffee chain — **5 shops,
12 months of operational data**. Transactions, menu, reviews, staff shifts, shop
metadata. The dashboard shows raw tables, numbers, lists. It is deliberately
**"dumb"** — it does not summarize, forecast, recommend, or explain anything.

Your job is to show us how you think about turning this into a product that uses
AI **where it actually helps**.

**Stack (what's already here):** Backend: Python + FastAPI, SQLite. Frontend:
single HTML file + vanilla JS, no build step. Data: SQLite database, pre-seeded.

The deliverables were `DISCOVERY.md` (discovery document), one end-to-end AI
implementation with a versioned system prompt, edge-case list, testing approach,
`EVALS.md`, and a model/provider choice with cost and latency notes — all
present in this repository as described above.
